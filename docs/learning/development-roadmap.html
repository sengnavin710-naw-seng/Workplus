Workforce Platform · บทเรียน 03

Phase บอกว่า “สร้างความสามารถอะไร” ส่วน UX และ Login บอกว่า “ส่งมอบมันอย่างไร”

ทั้งสองอย่างไม่ได้แข่งขันกัน เราจะทำเป็นชิ้นงานแนวตั้ง: ออกแบบ flow ขนาดเล็ก แล้วต่อ UI → Auth/API → Database → สิทธิ์และการตรวจสอบ ให้ใช้งานจบหนึ่งเรื่อง

คำตอบสั้น: ออกแบบ UX แบบ low-fidelity ของ Login และ onboarding ก่อนเล็กน้อย → ทำ Login ที่ใช้งานจบจริง → เริ่ม Phase 1 ส่วนงาน visual design ละเอียดให้ทำตามหน้าที่กำลังพัฒนา ไม่ต้องออกแบบทั้งผลิตภัณฑ์ล่วงหน้า

Capability roadmap

แต่ละ Phase ทำอะไร และมีเป้าหมายอะไร

Phase 0
Foundation

Monorepo, Web, Agent shell, PostgreSQL/Drizzle, Better Auth, tRPC และโครงสร้าง tenant

เป้าหมาย

ลดความเสี่ยงด้านการเชื่อมระบบ ให้มีฐานที่เพิ่มฟีเจอร์โดยไม่ปน web session กับ device credential

Phase 1
Privacy & trust controls

Policy version, consent, retention, audit log และ device enrollment/revocation

เป้าหมาย

ทำให้การเก็บข้อมูลในอนาคตมีเหตุผล สิทธิ์ ขอบเขต และหลักฐานตรวจสอบได้ ก่อนเริ่ม tracking

Phase 2
Visible time tracking

เริ่ม/หยุดงานที่ผู้ใช้เห็น, work session, timesheet และการตรวจแก้

เป้าหมาย

พิสูจน์คุณค่าหลักแบบ end-to-end โดยยังไม่เก็บชื่อแอป หน้าต่าง idle หรือภาพหน้าจอ

Phase 3
Application usage & active/idle

เก็บเฉพาะที่ policy อนุญาต พร้อมสถานะที่ผู้ใช้มองเห็นและ retention

เป้าหมาย

เพิ่มรายละเอียดเมื่อกลไกความยินยอม สิทธิ์ และความโปร่งใสพร้อมแล้ว

Phase 4
Aggregation

Background jobs และ summary tables สำหรับ dashboard

เป้าหมาย

อ่านรายงานได้เร็วโดยแยก raw data ออกจาก read model และยังตรวจย้อนกลับได้

Phase 5
Optional screenshots

ทำเฉพาะเมื่อมีความจำเป็นจริง พร้อม encryption, retention, access audit และ user visibility

เป้าหมาย

จำกัดฟีเจอร์ที่เสี่ยงด้าน privacy และค่าใช้จ่ายสูงที่สุด โดย Phase นี้สามารถไม่ทำเลยได้

Recommended order

ลำดับงานจริงจากจุดปัจจุบัน

1 · UX flow สั้น ๆวาด Login → เลือกองค์กร → Dashboard → Logout รวม loading/error/empty state
2 · Auth vertical slicePublic signup, login/logout, session, protected route และ workspace onboarding
3 · UI foundationกำหนด typography, spacing, color tokens, form และ app shell ขั้นต่ำ
4 · Phase 1ทำ consent + policy + enrollment + audit เป็น flow ที่ใช้งานได้จริงทีละชิ้น

Definition of next milestone

Milestone ถัดไปที่เหมาะสม

“ผู้ใช้สมัครด้วยอีเมล สร้าง Workspace เป็น Owner และเข้าสู่ Dashboard ที่ถูกป้องกันได้”
  • มี public registration ด้วย email/password
  • ผู้ใช้ที่ยังไม่มี Workspace ถูกส่งไป onboarding
  • ผู้ไม่มี session เข้า Dashboard ไม่ได้
  • tRPC authenticated procedure ตรวจ session และ organization membership
  • ยังไม่ใช้ browser session เป็น credential ของ Desktop Agent
ข้อควรระวัง: Public signup สร้างเฉพาะบัญชีเว็บ จากนั้น onboarding จึงสร้าง Workspace และกำหนดผู้สมัครเป็น Owner ส่วน Employee ที่ติดตั้ง Agent จะไม่จำเป็นต้องมีบัญชีเว็บ
